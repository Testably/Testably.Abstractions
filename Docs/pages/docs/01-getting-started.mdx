# Getting started

## Requirements

:::info[.NET Standard 2.0 or later]
The packages target .NET Standard 2.0 and 2.1, .NET 6, .NET 8, .NET 9, .NET 10 and .NET 11, so they also work in .NET Framework projects. Some members are only available on newer target frameworks; the pages that describe them say so.
:::

## Install the packages

Install `Testably.Abstractions` in your production projects:

<PackageInstall package="Testably.Abstractions" />

and `Testably.Abstractions.Testing` in your test projects:

<PackageInstall package="Testably.Abstractions.Testing" />

| Package                                     | Install it in                                                                                     |
|---------------------------------------------|---------------------------------------------------------------------------------------------------|
| `Testably.Abstractions`                     | Production code: contains `RealFileSystem`, `RealTimeSystem` and `RealRandomSystem`               |
| `Testably.Abstractions.Testing`             | Test projects: contains `MockFileSystem`, `MockTimeSystem` and `MockRandomSystem`                 |
| `Testably.Abstractions.Interface`           | Libraries that only consume `IFileSystem`, `ITimeSystem` or `IRandomSystem` and leave the choice of implementation to the application |
| `Testably.Abstractions.FileSystem.Interface`| Libraries that only need `IFileSystem`                                                            |

Both `Testably.Abstractions` and `Testably.Abstractions.Testing` pull in the interface packages transitively.

Optional [companion packages](/Abstractions/companion-libraries/) add [compression](./06-companion-libraries/01-compression.mdx), [access control](./06-companion-libraries/02-access-control.mdx) and [memory-mapped files](./06-companion-libraries/03-memory-mapped-files.mdx); each page shows how to install it.

## Register the abstractions

With `Microsoft.Extensions.DependencyInjection`:

```csharp title="Program.cs"
builder.Services
    .AddSingleton<IFileSystem, RealFileSystem>()
    .AddSingleton<IRandomSystem, RealRandomSystem>()
    .AddSingleton<ITimeSystem, RealTimeSystem>();
```

## Use the interfaces in your services

```csharp title="CatalogService.cs"
public class CatalogService(IFileSystem fileSystem)
{
    public void Export(string json)
    {
        fileSystem.Directory.CreateDirectory("exports");
        fileSystem.File.WriteAllText("exports/catalog.json", json);
    }
}
```

## Write your first test

In the test, replace the real implementation with the mock:

```csharp title="CatalogServiceTests.cs"
using Testably.Abstractions.Testing;
using static aweXpect.Expect;

public class CatalogServiceTests
{
    [Test]
    public async Task Export_ShouldWriteCatalogToExportsFolder()
    {
        // highlight-next-line
        MockFileSystem fileSystem = new();
        CatalogService sut = new(fileSystem);

        sut.Export("""{ "title": "Red Square" }""");

        await That(fileSystem.File.ReadAllText("exports/catalog.json"))
            .IsEqualTo("""{ "title": "Red Square" }""");
    }
}
```

That's it: your code now runs against an in-memory file system in tests, and against the real one in production.

:::note[About the examples]
The examples in this documentation are set in a gallery of abstract art: a catalog of artworks, exhibitions that open and close, and a night guard on patrol. They use [TUnit](https://tunit.dev/) and check results with [aweXpect](/aweXpect). Neither is required: the mocks work with any test framework and assertion library.
:::
