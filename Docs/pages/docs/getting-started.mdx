# Getting Started

## 1. Install the packages

Install `Testably.Abstractions` in your production projects and `Testably.Abstractions.Testing` in your test projects:

```powershell
dotnet add package Testably.Abstractions
dotnet add package Testably.Abstractions.Testing
```

| Package                                     | Install it in                                                                                     |
|---------------------------------------------|---------------------------------------------------------------------------------------------------|
| `Testably.Abstractions`                     | Production code - contains `RealFileSystem`, `RealTimeSystem` and `RealRandomSystem`              |
| `Testably.Abstractions.Testing`             | Test projects - contains `MockFileSystem`, `MockTimeSystem` and `MockRandomSystem`                |
| `Testably.Abstractions.Interface`           | Libraries that only consume `IFileSystem`, `ITimeSystem` or `IRandomSystem` and leave the choice of implementation to the application |
| `Testably.Abstractions.FileSystem.Interface`| Libraries that only need `IFileSystem`                                                            |

Both `Testably.Abstractions` and `Testably.Abstractions.Testing` pull in the interface packages transitively.

Optional [companion packages](./companion-libraries):

```powershell
dotnet add package Testably.Abstractions.Compression
dotnet add package Testably.Abstractions.AccessControl
dotnet add package Testably.Abstractions.MemoryMappedFiles
```

## 2. Register the abstractions

With `Microsoft.Extensions.DependencyInjection`:

```csharp title="Program.cs"
builder.Services
    .AddSingleton<IFileSystem, RealFileSystem>()
    .AddSingleton<IRandomSystem, RealRandomSystem>()
    .AddSingleton<ITimeSystem, RealTimeSystem>();
```

## 3. Use the interfaces in your services

```csharp title="CatalogService.cs"
public class CatalogService(IFileSystem fileSystem)
{
    public void Export(string json)
    {
        fileSystem.Directory.CreateDirectory("exports");
        fileSystem.File.WriteAllText("exports/catalog.json", json);
    }
}
```

## 4. Replace the real implementations in tests

```csharp title="CatalogServiceTests.cs"
[Fact]
public async Task Export_WritesCatalogToExportsFolder()
{
    // highlight-next-line
    var fileSystem = new MockFileSystem();
    var sut = new CatalogService(fileSystem);

    sut.Export("""{ "title": "Red Square" }""");

    await Expect.That(fileSystem.File.ReadAllText("exports/catalog.json"))
        .IsEqualTo("""{ "title": "Red Square" }""");
}
```

That's it - your code now runs against an in-memory file system in tests, and against the real one in production.

:::info[About the examples]
The examples in this documentation are set in a gallery of abstract art: a catalogue of artworks, exhibitions that open and close, and a night guard on patrol. They use [xUnit](https://xunit.net/) and [aweXpect](https://docs.testably.org/aweXpect/) assertions, but the mocks do not depend on either, so any test framework and assertion library works.
:::
